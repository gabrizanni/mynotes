The joint writer permits one observed native stream-idle recovery in the same
Agy invocation. A second native retry remains blocking; a final ERROR is never
publishable. Do not launch another whole generation to replace it.
A stream-idle log does not establish a universal Google API deadline. Model-step
wall time is not measured thinking time. Do not promise fixed Medium latency or
identical quality across effort settings; retain the user's selected model.

For new simple joint jobs (progressive_protocol=3), use the ordinary
`notes CODE --resume BATCH_ID` to reuse certified successful writing and finish
local metadata, layout and Word processing. Standard does not call a model
reviewer or repair worker. Preserve an ERROR result without publishing or
automatically restarting it. Do not construct diagnostic correction JSON for
the ordinary flow. A real unresolved blocking defect remains reported.

The procedures below describe saved historical jobs and explicit additional
review. They do not add phases or retries to new Standard requests.
For progressive v2 Agy jobs, inspect batch-status before acting. NEEDS_REVIEW
retains the failed unit/packet and does not grant another automatic attempt.
A corrected block is never automatically corrected a second time. Risk review is
split into at most three targets per call, not a new whole-lesson rewrite.
For an actual defect found after v2 writing, submit --review-defects against the
retained response hash. This permits only the first correction of a block whose
original allowance is unused. Inspect the sources and name exact blocks; do not
request an exhaustive review under Standard. The original generation is retained.
If the allowance is spent, stop at NEEDS_REVIEW; do not reset it or start another
whole generation. Failed explicit reviews keep the previous Word for reference,
but ordinary resume cannot certify that old result as a resolved defect.
An explicitly requested --regenerate creates a distinct revision; never infer it
from an ordinary --resume or hide a failed job behind a new one. Interrupted
intact prefixes may continue only in their saved conversation. Observed provider
truncation, stream errors and retries stop the owned invocation with logs retained.
Do not revive an ERROR result or modify raw receipts. This policy supersedes the
historical v1 retry/whole-group rules below only for jobs with progressive_protocol=2.

If saved successful writing is stopped only by wrong transcript IDs, inspect the
actual sources and use `notes CODE --resume BATCH_ID --review-references FILE.json`.
This explicit, local source-link rectification changes only evidence_ids, never
prose, source pages, page owners or teaching status. It is separate from a second
automatic narrative correction and invokes no model. The file binds the original
notes hash and each target hash; supply only verified current-lesson transcript
IDs and a concrete reason. JSON contract: {version:1, base_notes_sha256, reason,
changes:[{target:"organization"|"block", index, lecture_id, before_sha256,
evidence_ids:[...], reason}]}. Indices are zero-based in the original global
organization array or the stated lesson's blocks. Use at most 12 changes.
Hashes are SHA-256 of sorted compact UTF-8 JSON (ensure_ascii=false). The base is
the saved response's notes; each before hash binds the entire original target.
The stored reference-review receipt is reused automatically by later --resume.
Raw results and correction allowances stay unchanged. If the source
match is uncertain, stop for review; never guess references to make checks pass.

Use supported local recovery for metadata, checkpoint and Word errors; do not
edit MyNotes implementation, the installed runtime, raw responses or receipts
to turn a failure into success. Never accept an Agy ERROR envelope, weaken
slide-coverage checks or count a heading or unrelated citation as explanation.
Preserve the attempt. Diagnosis is an intermediate step: continue the verified
recovery path before reporting a genuinely unresolved external blocker.
Do not restart paid generation repeatedly or change model/effort without the
user's instruction. Requested settings are not proof of actual returned settings.
A successful writing transport retained after local validation failure must be
reviewed locally instead of regenerated. Standard uses one writing phase.
The writer permits only one automatic recovery from a temporary connection error,
with the same model and checkpoints. Writing and one necessary managed correction have no fixed elapsed-time cutoff: continue while making useful progress. If repeated actions stop producing progress, use the loop-recovery reminder and continue from the last valid checkpoint with a different permitted approach. Local validation retains its 2-minute limit and Word rendering its separate local timeout. Resuming preserves actual consumption. Do not add another
coordinator retry on top of it. Use `mynotes batch-status BATCH_ID --json` to read
actual progress; do not inspect implementation files or issue repeated Python probes.
Never say a process is running after its command failed unless batch-status shows
a live job. Distinguish content-ready, Word-ready, retry wait and stopped states.
Resuming must reuse certified responses after local structural-source review.
Never edit returned JSON, source citations or receipt hashes to satisfy coverage.
Only the managed, separately recorded hash-anchored targeted correction may fix
a real gap or defective passage, including replacements and moves. At most one
automatic correction per affected lesson and revision is allowed, within the
same saved correction checkpoint and requested model settings; no nested paid retries.
Before resuming a stopped batch, consult `mynotes recover-batch BATCH_ID --json`.
This is local diagnosis, not another model call. Apply --apply only for a verified
LOCALLY_RECOVERABLE result; a process failure stays preserved in a separate record.
NEEDS_CONTENT_REVIEW means preserve the original response and review concrete
defects against the sources. Reorganize and revalidate locally first; use the
bounded managed targeted correction when a real textual correction is necessary.
Never edit raw returned prose, evidence or receipts to force success, and never
restart whole-lesson generation to fix a local validation problem. Ordinary resume also checks saved compatible work.

An attempted writer with no certified successful response cannot be restarted
by ordinary resume. Preserve the failed attempt and report the actual blocker;
NO_LOCAL_RECOVERY is not permission to launch a second full generation.
A correction uses the existing one-attempt hash-anchored repair checkpoint;
reopening the chat or resuming does not grant a new correction allowance.
